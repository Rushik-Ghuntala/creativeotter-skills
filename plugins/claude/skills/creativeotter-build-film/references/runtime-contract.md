# CreativeOtter runtime contract

CreativeOtter adaptation, 2026-11-06. This is the execution authority for adapted skills; the preserved upstream snapshot is historical reference, not a live tool catalog.

## Current capabilities

The backend implements image creation/reference edits, private image uploads, saved-image galleries, account reads and Studio records. Provider discovery currently exposes only `image/nano-banana-2`. An opt-in motion renderer supports HyperFrames/GSAP JavaScript compositions, nested scenes, private project ZIPs, immutable editable revisions, bundled audio/video and MP4 output up to 30 seconds at 30fps. Its legacy CSS layout route remains compatible. It requires an enabled worker and workspace pricing; check html_rendering in live capabilities. Production is not enabled merely because these skills are installed. Filmed video generation, speech, cloning, music, sound effects, general media processing and feedback submission are not implemented. Their skills offer drafting or planning only. A host's independent media tools do not add a missing CreativeOtter billing contract. Only native **images** have that contract.

Use the actual tools exposed in this chat and `get_capabilities` when availability is uncertain. A loaded skill is not proof of authentication, media permission or provider availability. Model selection must follow the current catalog and exact schemas. Never silently replace an explicitly requested model, use another plugin's similarly named tool or use an image quote for another media category.

## Image execution and credits

Native-first reduces operating cost; native and API images both spend CreativeOtter credits. Obtain the live quote rather than assuming a packaged rate. Customer prices come from credit_units using the returned display scale (currently 1000 units per credit). Provider estimated_cost_label and max_cost_micro_usd are internal operating estimates, not customer retail prices. Do not quote them as the user's dollar cost or convert them to another currency. When asked for an image price, obtain a non-spending image quote through the image workflow, report its CreativeOtter credit amount, and do not execute. An explicit image request authorizes its requested count and quoted charge within any stated budget. Continue without another browser approval or chat confirmation. Estimate-only or planning-only requests stop before execution. Never add a paid test, hero draft, repair or extra take outside requested scope.

Native: prepare_native_generation → successful claim_native_generation → one actual host image call using the claim's fixed inputs → create_native_output → transfer the existing bytes as instructed → complete_native_output. Only claimed=true with reserved credits and an execution token authorizes the native call. Keep the token private. Provider: estimate_generation → generate_image with quote_id only → check_job with that same quote_id as needed. A route decision or quote is not execution authorization by itself.

Missing authentication, permissions, funds, pricing or provider configuration stops the affected route. Do not bypass CreativeOtter with a free native substitute. Never switch engines after a safety refusal, uncertain execution or successful generation whose saving failed. Reconcile the same operation; retry transferring the existing bytes. Report interrupted native work with report_native_outcome; a client report does not automatically refund it. Confirm saved delivery and the authoritative credit state before saying ready. See [recovery](job-recovery.md).

## Render execution

HTML rendering has its own bound quote, credit reservation and saved-output charge. Use prepare_render → render_design with the same render_id. render_design opens one auto-updating player; use get_render_status for any subsequent progress checks, without another UI card. Reserve get_render for explicit viewing/reopening of saved designs. Do not append a duplicate raw video embed to the final reply. Estimate-only calls stop before render_design. Rendering does not use fal.ai or the native/image billing contracts. The low-level backend supports PNG and MP4, but the creativeotter-render-html skill is reserved for motion graphics and animations: always request MP4 with visible movement. Route every still-image request, including static graphic designs, to creativeotter-generate-image. Existing images/logos may be animation ingredients; do not generate extra source images without a request. For brand motion, inspect relevant theme/character records and library references or the supplied website before authoring. Use actual available logos, mascots and product visuals rather than invented initial avatars. save_motion_project and revise_motion_project accept an assets array of owned ready image IDs and unused assets/ file paths, which the backend verifies and bundles privately; reference those relative paths in source. For a supplied company website, first call discover_brand_assets: it safely finds public artwork, privately imports it and returns thumbnails plus ready assets/paths. The host visually selects those real assets and passes the chosen attachments to save_motion_project; discovery is free and does not need fal.ai. Host downloads are a fallback if this tool cannot retrieve suitable files. The render worker never fetches remote media. Author projects with the current assistant, save_motion_project (or prepare_motion_upload → PUT ZIP → confirm_motion_upload), then pass the returned render_input to prepare_render. The dedicated worker runs JavaScript only in a sandboxed, network-isolated browser. Use get_motion_project and revise_motion_project for new immutable versions; saving versions and downloading ZIPs is free. Only MP4 rendering spends the live quoted credits. Use list_renders and get_render for existing designs.

## Saved work and records

For saved-image requests use manage_assets action list, kind output and the requested limit. Pass returned gallery_reference pairs to show_image_gallery in the requested order; provider generation IDs here are quote IDs. Asset IDs, generation IDs and quote IDs are not interchangeable. Never regenerate to reopen a gallery or invent a download link. Prefer the branded gallery over a host Canvas. If its tool is absent, use the actual returned authenticated gallery URL and explain the need to refresh discovery. Existing links refresh through their owning read tools; opening saved work spends no generation credits.

Studio records store directions and references, not generated media. Brand colors and character references must be explicitly included in later image inputs. Voice presets are scripts/directions, music records are briefs, and storyboards are planned shots. Budget targets are not enforced spending caps. See [Studio fields](studio-records.md) before writes. Preserve existing fields and IDs on updates. Archive/restore only requested records; do not promise unsupported deletion, image renaming, tags, bundle exports, settings changes or purchases.

## Replies, consent and recovery

Write for everyday users. Keep routine replies to one or two short sentences. Refer to image names or positions; keep internal IDs, technical timestamps, execution routing, dimensions, tokens and link expiry inside tools unless explicitly requested. Show the gallery/account panel without repeating its details. Never claim a download finished from a URL alone. A saved-plan response must not sound like generated audio or footage.

Use the existing OAuth connection. Account-only access does not grant media access; use current returned setup links when needed. Do not create duplicate connections, edit OAuth URLs or copy credentials. Reconnect for revoked access; refresh discovery only when authentication works but the chat has stale tools. A filesystem update does not update an active chat's loaded instructions.

Only use authorized likenesses; voice cloning is unavailable and must not collect recordings through image uploads. Feedback transmission requires explicit direction and an implemented destination; currently draft only. Keep private images, recordings, paths and conversation history out of unrelated services.
