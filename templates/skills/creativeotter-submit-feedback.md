# Submit requested feedback

CreativeOtter adaptation, 2026-11-01. Read [the runtime contract](references/runtime-contract.md) and [feedback guidance](references/workflows/feedback.md).

Confirm the user asked to send feedback and that `submit_feedback` belongs to the configured CreativeOtter connection. If unavailable, prepare a concise draft; do not send elsewhere. Do not infer authorization from a failed generation, a complaint, praise or an account question.

Use the live schema to describe the intended task, observed result, expected behavior and relevant model/tool/job ID. Exclude credentials, private media, conversation history and unnecessary personal data. Obtain specific consent before including sensitive details. Send once per requested report and confirm success only when the tool does.

Keep creative dissatisfaction distinct from technical malfunction. A report does not issue a refund, promise a fix or authorize another paid generation. Use current ledger evidence for billing questions and only server-returned support links.
